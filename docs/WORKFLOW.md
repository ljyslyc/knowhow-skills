# 工作流与衔接关系

这份文档写给**拿到这套 skill 的 agent**。目标是：不用读六个 SKILL.md，就能知道每个技能
吃什么、吐什么、什么时候该把它交给下一个。行文里的「你」指接手这套 skill 的 agent。

---

## 一、先看全局：一条流水线，六个可独立使用的环节

套件不是必须整条跑完的流水线。它是**六个自洽的技能**，其中几个能上下拼接。你完全可以只用
其中一个；拼接的价值在于省掉中间的手工搬运。

```
                    ┌─────────────────────────────────────────────┐
                    │  ① multi-search-engine  ← 所有联网环节的地基  │
                    │  L1 方向关键词 → L2 多引擎扇出 → L3 线索深挖  │
                    └───────────────┬─────────────────────────────┘
                                    │ 提供带结构、可溯源的素材
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
      ┌───────────────┐     ┌───────────────┐     ┌───────────────┐
      │ ② hv-analysis │     │ ③ khazix-     │     │ ⑥ aihot       │
      │ 深度研究→PDF  │     │   writer      │     │ 实时 AI 资讯  │
      │ 纵向+横向+交汇│     │ 公众号长文    │     │ （自带实时源，│
      └───────┬───────┘     └───────┬───────┘     │  不依赖①）    │
              │                     │             └───────────────┘
              │ 研究报告可作素材     │
              └──────────┬──────────┘
                         ▼
                 ┌───────────────┐
                 │ ④ leader      │  ← 也可脱离①②③单独用
                 │ 拆成任务书    │
                 └───────────────┘

      ┌───────────────────────────────────────────────────────┐
      │ ⑤ neat-freak  ← 横切：任何开发/产出告一段落后的收尾    │
      └───────────────────────────────────────────────────────┘
```

读法：

- **①是地基**。任何需要「搜得全」的环节都往下沉到它。
- **②③是两条并列的产出口**：②出研究报告，③出可发布文章。②的产出可以喂给③。
- **④是分发口**：把一个目标变成别的 agent 能独立执行的契约。
- **⑤横切所有**：不是流水线的一环，而是收尾动作。
- **⑥自带实时数据源**，与①并列而非从属——它查的是 AIHOT 的策展结果，不是通用搜索。

## 二、逐个交接契约

每个技能下面四行是硬契约：**触发 / 输入 / 输出 / 上下游**。写别的技能时依赖的就是这四行。

### ① multi-search-engine

| | |
|---|---|
| **触发** | 需要多源覆盖、交叉验证、行业/竞品扫描；单引擎搜会有遗漏 |
| **输入** | 一个主题 + 可选 profile（`company`/`industry`/`tech`/`person`/`concept`/`product`）+ 可选 `--comparison` |
| **输出** | `plan` → 方向化关键词计划；`run` → L2 抓取结果（JSON，含每个引擎的正文文本）+ L3 线索与追查词 |
| **上游** | 无（这是地基） |
| **下游** | → hv-analysis（作第一步素材）；→ khazix-writer（补弹药）；→ 任何需要事实依据的技能 |

关键接口：`run --out <path>` 写出的 JSON 可被 `leads --in <path>` 和 `drill --in <path>` 复用，
**不必重跑网络**。这是分层检索能被反复利用的原因。

```bash
python3 scripts/layered_search.py run --topic "赢创" --profile company --out /tmp/l2.json
python3 scripts/layered_search.py leads --in /tmp/l2.json --top 15
python3 scripts/layered_search.py drill --in /tmp/l2.json --intents patent,product
```

### ② hv-analysis

| | |
|---|---|
| **触发** | 要真正搞懂一个产品/公司/概念/技术/人物，期待系统性深度研究而非名词解释 |
| **输入** | 研究对象名（必需）；「为什么研究它」「特别关注什么」（可选，给了更准） |
| **输出** | `[研究对象]_横纵分析报告.pdf`（纵向 6000-15000 字 + 横向 3000-10000 字 + 交汇 1500-3000 字 + 来源清单） |
| **上游** | multi-search-engine（推荐：第一步就交给它做分层检索；没有就直接用宿主联网能力） |
| **下游** | → khazix-writer（报告可改写成可读性更强的文章）；→ leader（研究结论可转成待办） |

**上游依赖是可选的，不是必需的**。没有 multi-search-engine 时，按 SKILL.md 里给出的工具中立
联网指引照样能跑，只是素材组织得没那么结构化。

### ③ khazix-writer

| | |
|---|---|
| **触发** | 有素材或主题，要成篇的中文长文，且要卡兹克文风 |
| **输入** | 素材（brief / 链接 / PDF / 语音转文字 / 散乱想法）或「主题 + 几个要点」 |
| **输出** | 可直接发布的公众号长文（Markdown） |
| **上游** | multi-search-engine / aihot（补事实与时效弹药）；hv-analysis（拿研究报告当底稿） |
| **下游** | 无固定下游；产出即终态 |

注意：**素材不足时会先反问用户要更多信息**（想讲哪几个点、有无亲身经历）。这是设计行为，
不是失败——不要替用户编素材跳过这一步。

### ④ leader

| | |
|---|---|
| **触发** | 要把一个想法变成别的 agent 能独立跑完的任务书 |
| **输入** | 一句话想法；有代码库/文档/链接就一并给 |
| **输出** | ≤4000 字符的任务书（可粘贴即跑），含实测数字、禁区、防作弊验收、断点续跑 |
| **上游** | 可无；也可接 hv-analysis 的研究结论作为背景 |
| **下游** | → 目标模式里的执行 agent（本套件之外） |

**硬约束**：任务书里不许出现「来找我」。执行者与作者不共处一个会话、问不到人，
所以凡是没问的都必须在书里写成「我替领导拍的板」并给默认值。

### ⑤ neat-freak

| | |
|---|---|
| **触发** | 开发告一段落要收尾；文档与代码对不上；规则文件过期或打架；要干净交接 |
| **输入** | 一个项目目录；可选范围限定（如「只看文档，别动记忆」） |
| **输出** | 逐事实面状态报告（代码/运行态/文档/规则/记忆/工作区，每面一行结论 + 证据）+ 已同步的不一致项 |
| **上游** | 通常是某个项目刚改完代码/文档 |
| **下游** | 无；产出即终态 |

**横切属性**：它不是流水线的一环，而是任何一段工作结束后的收尾动作。破坏性清场（删分支/
worktree/临时库）默认只做只读预览，必须等用户看完汇报确认后才执行。

### ⑥ aihot

| | |
|---|---|
| **触发** | 想知道 AI 圈最近发生了什么（今天/近 7 天/某话题/某事件来龙去脉/AI 日报） |
| **输入** | 一个自然语言问题，无需准备 |
| **输出** | 中文 AI 资讯整理（按时间范围或话题），附可继续追问的入口 |
| **上游** | 无（自带实时数据源，不依赖 multi-search-engine） |
| **下游** | → khazix-writer（拿时事素材写文章）；→ hv-analysis（作为时效性补充） |

**为什么必须用它**：AI 动态变化快，任何模型的训练记忆都必然过时。它把问题直接交给 AIHOT
服务器实时查询，**不许用训练知识替代真实结果**。全程匿名只读，不得索要用户凭据。

## 三、常见组合路径

| 你想干什么 | 怎么串 |
|---|---|
| 摸清一个行业 / 竞品 | ① `run --profile industry --comparison` → ② hv-analysis 用素材写报告 |
| 写一篇有时效的深度长文 | ⑥ aihot 取当下热点 → ① 补事实 → ③ khazix-writer 成稿 |
| 把研究结论落成待办 | ② hv-analysis 出报告 → ④ leader 拆成任务书给执行 agent |
| 项目收尾交人 | ⑤ neat-freak 对齐文档/规则/记忆 → 汇报确认 → 清场 |
| 只用一件 | 六个技能都能单独跑，直接调即可 |

## 四、写新技能时必须遵守的迁移规则

这套 skill 的目标是**换任何宿主 agent 都能直接用**。所以：

1. **不写死宿主工具名**。不要写「用 WebSearch 搜」——写「用你环境里的联网能力搜」，并给一张
   宿主映射表。参照 `multi-search-engine/SKILL.md` 的 Step 0，那是范本。
2. **不写死宿主路径**。不要出现 `/mnt/.claude/skills/...` 这类绝对路径。要探测，不要假设。
3. **可选依赖要标注为可选**。缺了它技能仍应成立，只是慢一点或少一层。写明降级路径。
4. **描述面向第一次使用的人**。写清：这是什么、什么时候触发、什么时候**不要**用、怎么工作、
   你需要准备什么、你会拿到什么。避免只堆一串触发词。
5. **平台差异进 references**。路径、加载顺序、尺寸上限这类会变的事实，放
   `references/*.md` 并注明「以官方文档为准」，不要散落在 SKILL.md 正文里。

已按这套规则修过的地方：`multi-search-engine`（工具中立范本）、`hv-analysis`（移除硬编码路径
与宿主工具名）、`neat-freak/references/agent-paths.md`（补齐 WorkBuddy / OpenClaw）。

## 五、接手检查清单

第一次拿到这套 skill，按顺序做这四件事：

1. **确认能读文件**：读每个 `SKILL.md` 的 frontmatter，`name` 与目录名一致。
2. **确认有哪些联网能力**：按 `multi-search-engine/SKILL.md` 的 Step 0 表定位到你这台机器
   可用的抓取方式。
3. **跑一次确定性测试**（不需要网络）：
   ```bash
   python3 skills/multi-search-engine/scripts/test_layered_search.py
   # 期望：71 passed, 0 failed
   ```
4. **试跑一次 L1 规划**（不需要网络，只打印关键词）：
   ```bash
   python3 skills/multi-search-engine/scripts/layered_search.py plan --topic "测试主题"
   ```
   能看到方向化关键词，说明脚本与解释器都正常；再去跑需要网络的 `run`。
