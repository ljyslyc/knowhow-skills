# 周期性优化机制

本套件不是一次装完就不动的静态资产。这份文档规定**怎么攒证据 → 怎么改 → 怎么验证**，
让每一轮优化都有依据、可回滚、可比对。

## 一、优化从哪来：四类信号

| 信号 | 说明 | 记录位置 |
|---|---|---|
| **失败样本** | 跑技能时实际翻车的案例：检索被拦、报告跑偏、文风失守、拆解漏项 | `docs/feedback/failures.md` |
| **人工改写** | 用户对产出的二次改动——改了哪里，就说明哪里的默认值不对 | `docs/feedback/edits.md` |
| **触发偏差** | 该触发的没触发、不该触发的乱触发 | `docs/feedback/triggers.md` |
| **上游变动** | khazix-skills 上游更新、引擎改版、路径失效 | `git log` + 本文件 §五 |

**原则：先攒够 3 条同类信号再动手改**，避免为单个偶发案例把技能改歪。

## 二、改什么：按技能分层

| 层 | 内容 | 改它的门槛 | 归因难度 |
|---|---|---|---|
| L1 数据 | 引擎 URL、预设组合、类别归类 | 低，随时改 | 低 |
| L2 脚本 | `fetch_search.py` 的参数、解析、重试 | 中，需跑通测试 | 中 |
| L3 方法论 | 报告章节、写作禁区、自检体系 | 高，需多轮样本 | 高 |
| L4 触发 | frontmatter 的 `description` / 触发词 | 中，改动会影响召回 | 中 |

**改动顺序：从上往下**。能用 L1 数据解决的，绝不改 L3 方法论——方法论一改，历史产出就不可比了。

## 三、怎么验证：改动前后的 A/B

任何 L2 以上的改动，必须留下对照：

```bash
# 1. 固化一组"基准题"（3-5 个真实任务，覆盖本套件各技能）
#    放在 docs/benchmarks/，每题包含：输入 + 期望产出的判定要点

# 2. 改动前跑一遍，记录结果
# 3. 改动后再跑一遍，逐题比对
# 4. 只有"不劣于基准"才合并
```

### 基准题清单（初始）

| # | 任务 | 考察技能 | 判定要点 |
|---|---|---|---|
| B1 | 研究某竞品的近 3 年专利布局 | hv-analysis + 搜索 | 是否有专利明细表、有没有编造专利号 |
| B2 | 写一篇 4000 字行业观察长文 | khazix-writer | L1 禁用词零命中、L4 活人感通过 |
| B3 | 把一句想法拆成 agent 任务书 | leader | ≤4000 字符、含验收命令、无"来找我" |
| B4 | 同一主题覆盖中英日三语检索 | multi-search-engine | 三语引擎都出结果、去重正确 |
| B5 | 项目收尾对齐文档与记忆 | neat-freak | 找出全部不一致项、不误删 |

## 四、健康指标（每次优化后自查）

| 指标 | 目标 | 怎么量 |
|---|---|---|
| 搜索可用率 | ≥ 70% 引擎返回 200 | `fetch_search.py multi --preset quick` 成功数 / 总数 |
| 检索去重率 | 重复 URL 占比 < 30% | `--json` 输出后统计 |
| 报告反编造 | 编造数据/编号 = 0 | 人工抽检 + 溯源条数核对 |
| 文风合规 | L1 禁用词命中 = 0 | `khazix-writer` 四层自检 |
| 触发准确率 | 误触发 < 10% | 日常使用中记录 |

## 五、周期

| 周期 | 动作 |
|---|---|
| **每周** | 攒信号（§一），跑一次「搜索可用率」体检 |
| **每两周** | 处理积压信号，做 L1 数据类改动 |
| **每月** | 跑基准题（§三 A/B），做 L2 脚本类改动，更新 CHANGELOG |
| **每季** | 复核 L3 方法论与 L4 触发；同步上游 khazix-skills 变动 |

### 搜索层体检脚本（每周跑）

```bash
cd skills/multi-search-engine
python3 scripts/fetch_search.py multi --query "test" --preset quick --max-chars 100
# 退出码：0 全部成功 / 2 全部失败 / 3 部分失败
```

## 六、上游同步

```bash
# 拉取上游最新（本套件为独立仓库，不设 remote 时手动比对）
git clone --depth 1 https://github.com/KKKKhazix/khazix-skills.git /tmp/khazix-upstream
diff -ru /tmp/khazix-upstream/<skill> skills/<skill>
```

**同步策略**：
- 上游 L1/L2 改动 → 尽量合并
- 上游 L3 改动 → 先跑基准题，确认不劣化再合并
- 本套件的自有改动（如 `multi-search-engine` v4）→ 单独记录在 CHANGELOG，同步时注意不要被上游覆盖

## 七、版本与回滚

- 每次合并前打 tag：`git tag v0.1.0`、`v0.1.1` …
- 回滚：`git revert <commit>` 或 `git checkout <tag> -- skills/<skill>`
- CHANGELOG 必写「为什么改」，不只是「改了什么」
